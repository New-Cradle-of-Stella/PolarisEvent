# PolarisEvent 与 PEVT 实现总纲

## 1. 实现目标

PolarisEvent 将成为独立托管 PEVT 事件的解释型运行时，负责源码加载、静态校验、事件执行、`@` 指令分派、协程调度、事件间调用、异常诊断和生命周期清理。

最终执行链：

```text
.pevt 源文本
    ↓
词法、语法、名称、类型与静态控制流校验
    ↓
不可变的 PEVT 程序定义
    ↓
PolarisEvent 执行实例
    ↓
表达式、流程语句、自定义块、@ 协程、callevt 与原始桥
    ↓
受控 C# 原子服务与游戏功能
```

## 2. 已确定的边界

- PEVT 是解释型事件语言，不编译、缓存或写回 `.cmd`。
- 除 `$raw cmd` 外，PEVT 不进入原版 `EvReader` 和 `EV.readOneLine`。
- `@` 由 PolarisEvent 直接分派到已登记 C# 处理器，不先生成原版指令文本。
- PEVT 流程控制、变量、表达式、自定义块和异步句柄全部由 PolarisEvent 解释。
- PEVT 不加入类、对象、继承、泛型、反射或任意游戏 API 访问。
- 同步与异步 `@` 复用同一个 C# 组合协程；异步版只改变调度和所有权。
- 全部跨帧等待通过可取消、可诊断的 `PevtWait` 子类实现。
- `$raw cs` 只在文件显式声明 `enable cs` 后启用，并视为受信任能力。

## 3. 总体架构

### 3.1 语言核心

语言核心是无 Unity、无游戏依赖的纯 C# 模块，负责：

- UTF-8 源文本、行列与源码范围；
- token 与词法解析；
- 语法树和错误恢复；
- 标识符、变量、常量、参数、句柄与自定义块符号；
- 五种普通类型与表达式类型检查；
- `@` API 签名绑定；
- 标签、结构化流程与静态路径分析；
- `PEVTxxxx` 静态诊断。
- `.pactor` 人物目录 XML、人物/视觉/锚点定义与 `PEVT91xx` 诊断。

该模块同时供游戏运行时与 PolarisTools 使用，避免编辑器和真实执行使用两套语法规则。

### 3.2 程序定义与加载器

PolarisTools 把每个通过构建期静态校验的 `.pevt` 源文本使用 GZip 压缩并编码为 Base64 文本串，再嵌入与模组一起编译的生成 `.g.cs`。游戏加载模组时，生成注册器提交载荷，PolarisEvent 解压、二次校验并写入内存虚拟 `/event/<id>.pevt` 空间。

压缩只是模组分发形式，不是 PEVT 编译结果。详细契约见 `PEVT-嵌入注册与ID冲突规范.md`。

解压且通过运行时静态校验的源文本加载为不可变程序定义，包含：

- 事件 ID、模组归属和源文件身份；
- `enable cs` 与 `enable async` 能力标志；
- 已绑定外层事件体和自定义块；
- 变量槽、跳转目标、块签名和 `@` 处理器引用；
- 源码映射、内容哈希与定义代次。

运行实例固定使用启动时的定义代次，不在事件执行中途替换语法树。

### 3.3 执行引擎

执行引擎负责实际解释程序定义，包含：

- PEVT 值、未初始化状态与强类型运算；
- 文件、自定义块与 `exec` 临时环境；
- 显式执行帧栈，不依赖 C# 递归栈表示事件调用；
- 语句位置、分支、循环、`switch` 与绑定跳转目标；
- 确定的每帧执行预算与无进展检测；
- `PEVTRxxxx` 运行诊断与调用栈记录。

执行引擎只执行已绑定节点，不在每帧重新解析原始文本。`exec` 是唯一在运行时产生新 PEVT 片段定义的语法。

### 3.4 `@` 注册与中间层

`@` 系统分为三层：

```text
公开 @ API 签名
    ↓
有序组合协程
    ↓
强类型 C# 原子服务
```

- 注册表保存名称、参数、返回类型、能力、同步/异步模式与处理器引用。
- 同名重载只能依据完整参数类型和数量唯一选择。
- 处理器将高级 `@` 指令实现为原子 C# 方法的有序组合。
- 原子服务集中隔离游戏内部对象，PEVT 不持有 Unity 或游戏对象引用。
- 通用剧情能力与 Alice In Cradle 领域能力分开注册。

### 3.5 协程、等待与异步调度

- 同步跨帧 `@` 作为当前 PEVT 流程的附着协程执行。
- `_start` 变体使用同一协程工厂，但作为事件拥有的子协程独立调度。
- 协程只产出 `PevtWait`，不使用不透明 Unity yield 对象。
- 调度顺序、同帧结果选择和 `await any` 胜者必须确定可重现。
- `handler`、`await`、`status`、`kill`、`all` 与 `any` 统一查询调度器中的单一协程状态。
- 事件结束、替换、异常或卸载时，必须取消它拥有的全部子协程。

### 3.6 事件注册、调用与所有权

PolarisEvent 注册表以大小写敏感的全局事件 ID 查找 `/event/<id>.pevt` 程序定义，同时记录模组来源和冲突状态。

- 不同模组程序集注册同一 ID 时，沿用 Polaris Lang 的模式收集全部冲突，扫描结束后汇总为一条致命报告。
- 冲突时临时保留先注册定义、忽略后注册定义，保证同一次启动内行为稳定。
- 同一程序集内的重复 ID 优先由 PolarisTools 作为构建错误处理；运行时漏网情况记录警告并使用后注册定义。

- `callevt` 只在真正执行时解析目标，允许跨模组调用。
- 同步目标成为当前执行链的子事件，调用者等待它结束。
- `enable async` 目标可以异步子事件形式启动，并纳入父事件所有权树。
- 找不到目标、目标冲突或异步属性不符均是运行错误。
- 每个根事件、子事件、协程、原始桥会话和临时 `exec` 环境都必须归属到明确的执行树。

### 3.7 人物目录、原版别名与视觉资源

人物注册表与 `/event` 事件表相互独立。公开人物 ID 使用 `<namespace>:<local-id>`；原版固定为 `aic:*`，不把 `n`、`a`、`so` 等 CMD 短键暴露给普通 PEVT。

- Polaris 内置 `.pactor` 固定登记原版 18 个稳定说话人键：`_` 映射为无立绘的 `aic:narrator`，并把 `n/nb/nb2` 合并成 `aic:noel` 的三套 portrait。
- 原版 `TALKER_REPLACE` 的临时键只属于 `$raw cmd` 会话，不能进入全局人物表。
- 模组作者使用 XML `.pactor` 登记人物、显示资料、world sprite、portrait、UI portrait、appearance 和自定义 anchor。
- PolarisTools 生成强类型 `.g.cs` 注册器；XML 不能写任意 C# 类型或方法，只能选择允许的 PolarisRes 资源字段。
- 原版 PXLS 通过 PolarisRes 的只读 `game-pxls` 桥借用原版 `MTI/MTRX/PxlsLoader` 结果；自定义 PXLS/MImage 通过 PolarisRes 自动绑定字段延迟取得。
- `@say` 和 `@actor_*` 先解析人物目录，再解析视觉/站位并等待资源；失败不得创建半成品图层。
- 人物目录冲突按大小写敏感最终 ID 汇总报告，内置 `aic` 命名空间不可覆盖。

详细契约见 `PEVT-人物目录与原版别名规范.md`，固定数据见 `Event/Pevt/Content/AliceInCradle.BuiltinActors.pactor`。

### 3.8 原始桥与动态执行

- `$raw cmd` 使用独立原版 EV 桥，把原始文本作为一次受控会话执行并等待结束。
- 原版 EV 是全局前台状态机，因此原始桥必须独占、串行并能处理取消与清理。
- `$raw cs` 由独立受信任 C# 执行器处理，只注入显式传入的普通值副本，并校验返回类型。
- `exec` 使用语言核心在运行时重新分析片段，绑定到当前允许的外层环境，并受独立深度与步数限制。
- 原始桥和 `exec` 不得绕过事件所有权、取消、诊断或清理规则。

### 3.9 资源与会话状态

PolarisEvent 应把原版分散的 `EvtCacheRead` 和全局 flag 改为明确服务：

- `@` 处理器可声明能从常量参数提取的资源依赖；
- 事件启动前可预取已知资源；
- 运行时动态资源使用 `PevtResourceWait` 等待；
- 人物视觉资源统一投影为 PolarisEvent 只读 handle，原版资源是借用、自定义资源由来源 PolarisRes owner 持有；
- UI、输入、镜头、图层、遮罩和音频占用归当前事件会话所有；
- 事件结束时统一恢复临时状态，持久进度变更不自动回滚。

### 3.10 诊断、跟踪与调试

- 静态错误使用 `PEVTxxxx`，运行错误使用 `PEVTRxxxx`。
- 运行诊断包含事件 ID、模组、源路径、行列、事件/自定义块调用栈、协程 ID、句柄和内部异常链。
- 执行引擎应支持语句级跟踪、协程与等待状态快照、执行预算统计和事件所有权树查看。
- 调试功能不得改变正常调度顺序或依赖原版 EV 调试器。

### 3.11 PolarisTools 与模组分发

PolarisTools 使用同一语言核心提供：

- `.pevt` 内容类型、高亮、补全和快速信息；
- `.pactor` XML 模型、项目项模板、参数编辑器、人物/视觉 ID 预览与资源字段选择器；
- 实时语法、类型和控制流诊断；
- `@` API 签名、参数域与资源 ID 提示；
- 定义跳转、引用查找与格式化；
- 将原始 `.pevt` 的 UTF-8 字节用 GZip 压缩、Base64 编码，并把压缩串、ID、项目相对路径、未压缩长度和 SHA-256 嵌入模组注册代码。
- 将 `.pactor` 生成只含不可变人物数据与延迟资源访问器的 `.g.cs`；不把 XML 当作运行时脚本执行。

工具侧可以在构建时拒绝有静态错误的源文件，但不向模组嵌入已编译 `.cmd` 或可执行 PEVT 字节码。游戏侧解压后仍以原始 PEVT 源文本为真相并执行自己的加载校验。
